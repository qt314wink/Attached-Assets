Practical Application: Promptware Blueprints
To solidify his new role, Bart compiled a collection of practical Promptware Blueprints—ready-to-use formulas that translated common design challenges into deterministic, system-level instructions for the AI. These blueprints ensured his team moved beyond simple "generate a button" requests to architecting reusable, logic-driven outcomes.
Blueprint 1: Token-Driven Component State Generation
Goal: Generate all necessary states for a complex component (e.g., a form input) purely by referencing design tokens, eliminating manual style adjustments.
Logic Element	Detail/Value (Design Token Examples)
Profile	Act as a Front-End Design System Engineer specializing in component behavior and atomic design principles.
Instruction	Generate the UI properties (CSS/Figma JSON) for the 'Text Input' component across four states: default, hover, focus, and error.
Context	Use the provided Design Token Map. The component must maintain a fixed height (size-500) and the standard corner radius (radius-sm).
Constraints	Default State: background: color-neutral-100, border: border-width-100 color-neutral-300. Error State: border-color: color-feedback-error-500. Focus State: box-shadow: shadow-ring-focus. Only use tokens from the provided map.
Output	Format the response as a single JSON object where the keys are the state names and the values are the full style definitions (including all properties like color, padding, and border).
Blueprint 2: Accessibility Audit and Refinement (Using RSIP)
Goal: Automatically audit a newly generated UI element for accessibility (WCAG 2.1 AA) and self-correct the output in a single run. (Leveraging Recursive Self-Improvement - RSIP).
Logic Element	Detail/Value (The 4-Step RSIP Command Chain)
Profile	Act as a Certified Accessibility Specialist (CPACC, WAS). Your sole purpose is to ensure WCAG 2.1 AA compliance in generated code snippets.
Step 1 (Generate)	Generate the HTML/CSS for a marketing banner component that includes a dark background (color-brand-900) and a primary call-to-action button.
Step 2 (Evaluate)	CRITIQUE the generated output against WCAG 2.1 AA Success Criterion 1.4.3 (Contrast). Specifically, check the contrast ratio between the text color and the color-brand-900 background, and the button's text/background contrast.
Step 3 (Identify)	PINPOINT the specific failure(s). If contrast fails, state the exact required vs. provided ratio and suggest the necessary color token adjustment (e.g., changing from color-neutral-100 to color-neutral-0).
Step 4 (Refine)	REWRITE the entire original HTML/CSS output, incorporating the suggested color correction from Step 3 to ensure full compliance. Output only the final, corrected code block.
Output	Final, corrected HTML/CSS component code block.

Blueprint 4: Multi-Agent UI Flow Orchestration (Ensembling)
Goal: Ensure systematic, structured UI flow by sequentially tasking specialized agents.
Agent Name	Role/Action (PICCO Structure)	Flow/Trigger for Next Agent	Output
Agent A (The Planner)	P: Senior UX Strategist. I: Outline the 7 key steps for user creation. C: Target: B2B. Constraints: Max 5 steps with user interaction.	Output: Ordered Step List $\rightarrow$ Trigger: Agent B	Markdown list of sequential steps (e.g., [Step 1: Type Selection], [Step 2: Basic Info]).
Agent B (The Detailer)	P: Visual/Interaction Designer. I: For Step 2 (Basic Info), generate a wireframe based on the existing token map. C: Use tokens. Constraints: Use input-lg only.	Output: Wireframe JSON $\rightarrow$ Trigger: Agent C	JSON representation of the wireframe for Step 2.
Agent C (The Validator)	P: Legal/Compliance Officer. I: Review Agent B's output to ensure data collection fields are compliant (e.g., GDPR, CCPA). C: Must include mandatory consent checkboxes.	Output: Compliance Report $\rightarrow$ Final Output	Boolean Pass/Fail report. If fail, provide a bulleted list of mandatory fields to add.
